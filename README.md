# LogLineAlign

Merge multiple UTF-8 log files into one chronological timeline using a Node.js CLI or a standalone, completely offline browser page. Inputs can be unsorted; multiline entries, duplicates, and nanosecond precision are preserved. Both interfaces use the same TypeScript engine.

## Build

Install Node.js 24 or newer, [pnpm](https://pnpm.io/installation) 12.8.1, and Make. From the repository root, run:

```sh
make setup
make check
make
```

This creates `dist/loglinealign.html` and `dist/loglinealign.js`. Each is self-contained and can be copied elsewhere. The browser page needs no server or installed runtime; the CLI needs Node.js 24+. See [development instructions](docs/development.md#build) for individual build targets and cleanup.

## Offline browser

1. Open `dist/loglinealign.html` in a modern browser. All log processing stays on your device; no uploads or network access are required.
2. Drop your log files onto the page or select **Choose files**. They are selected and merged automatically. Leave **Format override** blank unless automatic detection reports a problem.
3. For timestamps without offsets, set each **File timezone** to its source's UTC offset, or use **Fallback timezone** in **Merge Settings** if they share one. Select **Remerge** after changing these settings.
4. Review the timeline. Use **Search / Filter** to keep matching lines, or **Merge Settings** to reverse the order or hide filename prefixes.
5. Use **Copy** or open **Download** to save the result. Both include all retained lines, including those outside the visible preview. Clear the filter to export the complete merge.

Format, timezone, and time-adjustment edits remain pending until you remerge; downloads are disabled while settings are pending. The page includes **Formats & usage** help for offline use. See the [browser guide](docs/browser.md) for detailed controls and filtering behavior.

## CLI

Run these commands from the repository root, replacing the example filenames with your logs. Put all options before input paths.

```sh
# Merge to the terminal.
node dist/loglinealign.js app.log database.log

# Save to a file; interpret timestamps without offsets as UTC.
node dist/loglinealign.js --timezone UTC -o merged.log app.log database.log

# Assign different offsets to logs whose timestamps omit them.
node dist/loglinealign.js --file-timezone east.log +02:00 \
  --file-timezone west.log -05:00 -o merged.log east.log west.log
```

Choose offsets that match the source logs. Output includes source filenames by default; use `-N` to omit them, `-r` for newest first, and `-v` for diagnostics. Use `--help` or the [CLI reference](docs/cli.md) for all options and advanced examples.

**Never run `node dist/loglinealign.js app.log > app.log`.** Shell redirection can truncate the input before the application starts. Use `-o` for output protection; it rejects destinations that refer to an input. An existing non-input output file can be replaced.

## Timezones and formats

Automatic detection supports full year-first dates and times, such as `2026-10-02T14:35:07Z` or `2026-10-02 14:35:07.123+02:00`. Other supported formats need an explicit override; see the [format reference](docs/formats.md#timestamp-rules).

**Assign the correct timezone to logs whose timestamps lack an offset.** Explicit timestamp offsets always take precedence. When every nonempty selected file contains offset-free timestamps and no timezones are assigned, the tool warns and assumes UTC. That assumption can misorder events from different time zones. Mixed selections and partial assignments may require an explicit fallback; see the [timezone rules](docs/formats.md#missing-timezones-and-the-utc-assumption).

Per-file time adjustments correct known constant clock errors. They change ordering without rewriting the original timestamp text, so displayed times may look out of order. Named timezones and daylight-saving rules are unsupported.

## Scope and verification

Designed for a handful of roughly 10 MB text files, with all data held in memory. Inputs must be UTF-8 text with supported timestamps. Compressed logs and live tailing are unsupported. Continuation lines stay with their entry, but browser filtering evaluates individual lines and can omit parts of a multiline entry.

There is no dedicated automated application test suite. See [development and verification](docs/development.md#verification) for build checks, manual checks, and the demo's limited automated validation.
