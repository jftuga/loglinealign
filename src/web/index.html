Formats & usage

Add files to merge automatically. Uncheck to exclude; the trash button removes a loaded file without changing it on disk. Timezone and format changes apply with Remerge or the next automatic merge.

Automatic formats: YYYY-MM-DD[T]HH:mm:ss, YYYY-MM-DD HH:mm:ss, YYYY/MM/DD HH:mm:ss. Optional dot/comma fractions (up to nine digits) and attached Z, ±HH:MM, or ±HHMM offsets.

Automatic detection consumes complete fractions and offsets and prefers one full timestamp over date-only message text, such as a BIOS date or --since 2026-09-08. Leave the format field blank for these logs. Two date-and-time candidates still require a distinguishing override. The error lists possible formats from valid supported timestamps on the failing line, including exact fractions and offset tokens. Copy one into Format override without the surrounding quotes; it may still need distinguishing literals and must fit the entire file. Suggestions are not applied automatically. Duplicate formats appear once; invalid or unsupported candidates are omitted, and the error says none if no valid supported candidates exist. Malformed or incomplete timestamps remain errors.

Override tokens: YYYY MM DD HH mm ss, one to nine S digits, Z (Z or colon offset), ZZ (compact offset). Override fields are required with exact widths. Nonblank overrides preserve literal leading and trailing spaces; a trailing literal separator may precede message text. Literal letters go in brackets, such as [T]. Numeric day/month record timestamps need an override, for example DD/MM/YYYY HH:mm:ss.

Explicit epochs: epoch-s (optional decimal fraction), epoch-ms, epoch-us, epoch-ns (integers). Multiple matching timestamps on one line are errors. Epoch overrides reject recognizable calendar dates and leading clock-only records; joined values such as 123-456 are not standalone epochs.

One format per file. Complete dates only; named timezones and leap seconds are unsupported. Leading lines stay before their first entry; subsequent continuation lines follow their preceding entry. Nonempty files without timestamps are errors. Empty files are ignored.

If every nonempty selected file contains timestamps without a timezone and no fallback is supplied, UTC is assumed with a visible warning. Explicit offsets are preserved. If other selected files have only explicit offsets or epochs, supply a fallback timezone. The warning is never included in downloads.

Filter logs keeps matching physical lines in both preview and download. Select Invert match to keep nonmatching lines, like grep -v; combine it with any matching option. The Aa, underlined ab, and .* buttons toggle case sensitivity, whole-word matching, and JavaScript regular expressions. Hover or focus a button for its description. Search original text, not generated filenames. Regex anchors apply per line; enter patterns without / delimiters. Whole words use Unicode letters, marks, numbers, and underscores as word characters. The preview highlights all nonoverlapping matches; source labels and downloads have no highlights. Zero-width matches have no visible highlight. Inverted results have no matches to highlight. An empty query shows all lines, even with inversion enabled. Clear restores all lines while preserving options. Invalid or slow patterns, including slow highlight matching, disable downloading until corrected; simplify or clear a timed-out filter to recover.

Source filenames are right-justified with spaces inside brackets, aligning closing brackets to the longest selected label (including duplicate-name suffixes). Preview and download use the same width, even when filtering. Select No filename (--no-filename) to omit prefixes from both immediately, without reparsing.

Preview rows are virtualized. Download saves all retained lines as plain text, or the complete merge when the filter is empty. Original ANSI sequences, if present in a log, remain literal text. All processing stays local; this page makes no network requests.
